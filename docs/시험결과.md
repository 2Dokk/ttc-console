# 신뢰성 시험 결과서

통신 연동이 **정상일 때가 아니라 깨졌을 때**를 기준으로 검증한 결과를 정리한다.
시험 항목마다 대상 요구사항, 시험 조건, 판정 기준, 결과를 남긴다.

- 시험 일자: 2026-10-19 ~ 10-22
- 대상: `2Dokk/ttc-console` (커밋 `f5de57e` 기준)
- 자동 시험 **31건 전부 통과**. 로컬 PC와 GitHub Actions 양쪽에서 실행.

---

## 1. 시험 환경

| 항목 | 값 |
|---|---|
| 지상 SW | Java 21, Spring Boot 3, PostgreSQL 16 (Testcontainers로 실제 DB 기동) |
| 통신 채널 | 시뮬레이션. 유실률·비트 오류율·연속 손실·지연 흔들림을 설정으로 조절 |
| 기본 조건 | 업링크 유실 10%, 다운링크 유실 5%, 비트 오류 2%, 지연 120 ± 30 ms |
| 전송 설정 | 윈도우 4, 재전송 타이머 3초, 재전송 한도 12회 |
| **재현성** | 난수 시드 고정(기본 `20260918`). 같은 시드면 같은 고장 순서가 재현된다 |
| 시간 | 시뮬레이션 시계로 가속(최대 ×1000). 재전송 타이머만 실제 시각 사용 |

**고장 주입 수단**
1. 프레임 유실 — 설정 확률로 프레임을 통째로 버림
2. 비트 오류 — 프레임의 임의 비트 1개를 뒤집음 (CRC 검출 대상)
3. 연속 손실 — 정상/악화 두 상태를 오가며, 악화 상태에서 연속 유실
4. 지연 흔들림 — 도착 순서가 뒤바뀔 수 있음
5. 교신 단절 — 궤도 계산에 따른 자연스러운 LOS, 또는 유실률 100%

## 2. 시험 항목과 결과

### 2-1. 오류 검출 (SYS-13)

| ID | 조건 | 판정 기준 | 결과 |
|---|---|---|---|
| T-CRC-01 | 표준 입력 `"123456789"` | CRC = `0x29B1` | **합격** |
| T-CRC-02 | 명령 프레임의 **모든 비트를 하나씩** 뒤집음 (전수) | 전부 폐기 | **합격** |
| T-CRC-03 | 텔레메트리 프레임의 **모든 비트를 하나씩** 뒤집음 (전수) | 전부 폐기 | **합격** |
| T-CRC-04 | 잘린 프레임, 빈 입력 | 폐기 | **합격** |
| T-CRC-05 | 실행 중 비트 오류 주입 (업링크 15%, 다운링크 15%) | 주입 수 = 검출·폐기 수 | **합격** (업링크 5/5, 다운링크 61/61) |

> T-CRC-02·03은 임의 샘플이 아니라 **프레임 길이 × 8개 비트를 모두** 뒤집어 확인한다.

### 2-2. 명령 전달 신뢰성 (SYS-05)

| ID | 조건 | 판정 기준 | 결과 |
|---|---|---|---|
| T-TC-01 | 교신 불가 중 명령 3건 등록 → 교신 시작 | 등록 순서대로 송신, 순번 1·2·3 | **합격** |
| T-TC-02 | 명령 6건, 윈도우 4 | 미확인 프레임이 4개를 넘지 않음 | **합격** |
| T-TC-03 | 응답 없이 타이머 경과 | 미확인 프레임 전부를 순서대로 재전송 | **합격** |
| T-TC-04 | 수신 확인이 실행 보고보다 늦게 도착 | 실행 완료 상태가 되돌아가지 않음 | **합격** |
| T-TC-05 | 위성이 선행 조건 불충족으로 거부 | 도달은 확인되고 상태는 '거부됨' | **합격** |
| T-TC-06 | 만료·취소된 명령 포함 | 해당 명령이 순번을 소모하지 않음 | **합격** |
| T-TC-07 | 업링크 유실 40%, 수신확인 유실 30%, 명령 12건 | 1~12번 순서대로 정확히 한 번씩 실행 | **합격** |

### 2-3. 장시간 고장 주입 (SYS-05, 종합)

| 항목 | 내용 |
|---|---|
| 조건 | 유실 40% · 비트 오류 10% · 교신 120초 / 두절 60초 반복 · 명령 30건 |
| 반복 | 난수 시드 8종 (1, 2, 3, 5, 8, 13, 21, 34) |
| 판정 기준 | ① 모든 명령이 정확히 한 번 실행 ② 실행 순서 = 등록 순서 ③ 종료 시 전부 수신 확인 |
| 결과 | **8회 전부 합격**. 최악의 경우에도 시뮬레이션 15분 이내 전달 완료 |

### 2-4. 링크 장애 시 거동 (SYS-14)

|---|---|---|---|
| T-FOP-01 | 업링크 유실 100% | 한도(설정값) 도달 시 송신 중지 + 경보 | **합격** |
| T-FOP-02 | 중지 상태에서 추가 틱 | 더 이상 송신하지 않음 | **합격** |

| T-FOP-04 | 실행 환경에서 재현 (유실 100%) | 12회 송신 후 중지(39초), 복구·재개 후 13회째 실행 완료 | **합격** |

## 4. 시험으로 발견한 결함

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 운용자가 송신을 재개해도 즉시 다시 중지됨 | 재전송 한도를 **누적 송신 횟수**로 판단. 재개해도 누적값이 그대로라 매번 한도 초과로 판정 | 한도를 **재개 시점부터 다시 세도록** 변경. 누적 이력은 보존 |
| 2 | 재시작 후 상태 이력이 겹쳐 기록됨 | 미션 시각이 현재 시각으로 초기화되어, 앞당겨 둔 시각의 기존 기록과 구간이 겹침 | 저장된 가장 늦은 시각부터 이어서 시작하도록 변경. 재발 방지 시험 추가 |

두 결함 모두 **정상 경로에서는 드러나지 않고**, 장애 상황·재시작 경계를 시험했기 때문에 드러났다.

## 5. 미검증 항목 (한계)

| 항목 | 사유 |
|---|---|
| 교신 중 유실된 텔레메트리의 복구 | 복구 기능 자체가 미구현 (누락 집계만). 다운링크 재전송 절차와 레코더 비우기 정책이 함께 필요 |
| 장시간 연속 운용 (수 시간~수일) | 단발 시험과 반복 시험만 수행 |
| 성능 한계 (동시 명령 수, 처리량) | 정량 목표를 세우지 않았음 |
| 운용자 화면 자동 시험 | 타입 검사·빌드만 자동화, 화면 동작은 수동 확인 |
| 보안 (명령 위조·재생 공격) | 범위 밖. CRC는 자연적 오류만 검출하며 위조를 막지 못함 |
